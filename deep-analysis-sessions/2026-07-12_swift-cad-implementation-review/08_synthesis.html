swift-CAD 実装レビュー

要件妥当性、アーキテクチャ、幾何・トポロジー、公開API、交換、テスト/CIの複数観点から再評価。

結論: pre-v1の契約とfail-closed境界は改善したが、計画した「単一の幾何学的真実を使うCADカーネル」は未実装。現状は基盤契約＋既存限定カーネルの整理段階であり、M2以降の受入完了とは判定できない。

計画に対する到達状態

Milestone判定根拠
M1 開発基盤部分達成
remote固定依存とbuild経路は成立。AST検査、責務分割、一対一のCapability証明は未達。
M2 Geometry / Topology骨格
新型は存在するが実評価の正本ではない。交差、adaptive precision、必須p-curve、曲面体積検証が未完。
M3 Feature slices部分達成
限定evaluatorsは多いが一般Booleanと後半feature群は未実装。垂直sliceの完了証明がない。
M4 公開経路統合部分達成
CADCommand導入は有効。一方でAgent固有query、PersistentName入力、generic capability fallbackが残る。
M5 Constraint / Selection / Exchange骨格
型と拒否境界はあるが、solver、stable recovery、STEP/IGES round-tripはない。

バーはLOC比率ではなく、受入条件への ordinal assessment を見やすく投影したもの。

正本経路の実態

CADCommand→ CADIR FeatureOperation→ CADIR Curve3D / Surface3D→ CADIR BRepModel→ Mesh

CADGeometryはこの主要経路の正本に入っていない。Package上もCADIRはCADGeometryへ依存せず、外部targetからのimportは実質BooleanPipelineだけである。

重大指摘

BLOCKER

1. Exact geometryが二重化

B-repのGeometryStoreはCADIR独自型を保持し、新しいCADGeometryは評価器へ切り替わっていない。モジュール追加はできているが、正本置換は未達。

BLOCKER

2. Capability Ledgerが実行可能契約ではない

publicAPIs/testFixturesは全entryで空の既定値。CIはLedgerとcatalogのID集合だけを比較し、実装・API・fixtureを検証しない。

HIGH

3. Booleanは固定9 phaseを実行していない

operand validationとbroad phaseの後、intersectionからsewingまでをbox backendへ一括委譲する。phase enumは診断可能なアルゴリズム境界になっていない。

HIGH

4. Validated B-repの意味が弱い

coedge p-curveがoptionalで、標準評価はvalidatePcurvesを呼ばない。曲面shellはline-only volume検査から正常returnし得る。

HIGH

5. Stable selectionはPersistentNameのordinal投影

provenance、geometry signature、ambiguity resolverはなく、入力featureの全Subshapeを親集合にするため、実際のsplit/merge対応関係を表現しない。

HIGH

6. Constraint solverは未置換

dimensionを順番に直接書き換える実装であり、DOF/Jacobian/forward AD/LM、under/over/conflicting/singular診断はない。

HIGH

7. STEP / IGESは安全なstub

mesh fallbackを拒否する点は正しい。ただしexact writerは常にunsupported、importもtopologyを再構築しないため、exchange受入条件は未達。

HIGH

8. 要件が実装に合わせて縮小

SPECはfull solverを現行scope外、Booleanをaxis-aligned box subsetと明記。現状説明としては正直だが、合意済みゴールの達成判定には使えない。

MEDIUM

9. Meshが実質必須

exact B-repを検証後、meshが空ならdocument evaluation全体を失敗させる。派生mesh障害が正本評価を無効化する設計になっている。

MEDIUM

10. M1の品質ゲートが未完

policy scannerはtoken masking＋regexでAST/compiler basedではない。CI test timeoutは30秒ではなく300秒。巨大test/sourceも未分割。

確認できた良い変更

  • swift-OpenUSDをremote fixed revisionに変更し、macOS/WASM build経路をCI化。
  • schemaをpre-v1 exact versionにし、主要enum decoderでunknown keyを拒否。
  • KernelError、SubshapeID、TopologyLineage、CADCommandを導入。
  • STEP/IGESでmeshをCAD形状として偽装せず、resource limitを持つfail-closed境界に変更。
  • feature結果を最終B-repに合成後に検証し、generated name/lineageの構造検証を追加。

修正の優先順

  1. Canonical cutover: CADGeometryをCADIRの並列表現ではなく唯一のgeometry contractにし、CADTopology/CADModelingへ責務を移す。
  2. Executable ledger: capabilityごとにtyped input envelope、public command/query、evaluator、fixtureを必須化し、CIでsymbol/test manifestを検証する。
  3. Topology hard gate: solid/sheet別invariantを定義し、p-curve、curve-on-surface residual、orientation、manifold、watertight、volumeを評価完了条件にする。
  4. Vertical slices: primitive→extrude→revolve→general Booleanを完了させてから次のfeatureへ進む。phaseごとにtyped failureとlineageを返す。
  5. M5 algorithms: stable resolver、numerical solver、exact STEP/IGESを独立stubではなく同じcanonical geometry上に実装する。
Primary evidence: repository source, CAPABILITY_LEDGER.md, SPEC.md, and CI configuration at commit 1060739. No external CAD oracle was used.
