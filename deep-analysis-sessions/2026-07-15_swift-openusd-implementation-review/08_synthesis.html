Architecture

SdfLayer、SdfSpec、SdfFieldValueを中心にreader、writer、compositionを接続し、文字列中心の旧経路から大きく前進した。

Interop

Swift生成物の公式検証と、公式生成物のSwift読込の両方向が成立。単なるself-round-tripより強い証拠である。

Performance

借用byte境界と回帰ゲート

USDByteStorage/USDByteSlice、lazy token string、benchmark baselineと10% regression thresholdを導入した。

Safety

USDC decoderを大幅に強化

section境界、展開率/展開size、value recursion depth、residual checksを備え、compressed path traversalも反復化されている。

優先指摘

P1

swift-CADはrevisionだけ更新できない

USDSceneReader必須APIはUSDByteSliceへ移行したが、CADUSDC/CADUSDZ adapterはData版だけを実装する。USDCLayer/readLayerも公開契約から外れ、USDErrorのcase追加でmapping switchも非網羅になる。

P1

共通のimport処理予算がない

USDCの局所上限は良いが、byte数、entity数、nesting、iteration、時間をUSDA/USDC/USDZ/composition全体へ通す公開契約がない。legacy USDC pathとnested USDZには明示depth budgetのない再帰が残る。

P2

canonical stateが二重化し得る

SdfLayerはspecsをsingle source of truthと説明する一方、derivedなprimTransformsとresetXformStackPrimPathsをpublic mutableで保持する。

P2

Sendable契約がplatform依存

composition cacheはDarwinだけSendable。非Darwin/WASMはNSLock実装でconformanceがない。Synchronization.Mutex<State>へ統一するのが明快である。

P2

capability gateが完全性を証明しない

UNSUPPORTED_FEATURES.jsonは空で、checkerはunsupportedFeatureの直接生成数しか見ない。parityはpartial/blockedを許容するため、対応入力・出力・失敗・fixture・oracleを結ぶledgerが必要。

P2

巨大責務単位と診断欠陥

最大test fileは10,870行、USDAReaderは6,503行。複数のerror stringで(identifier)等が文字列のまま出力され、typed diagnosticsの観測性を落としている。

推奨する実装順

  1. swift-CAD adapter cutover: Data入口を残す場合も内部はUSDByteSliceへ統一し、legacy layer APIを削除、追加されたUSDErrorを型付きで写像する。
  2. USDReadingLimits: bytes、entities、nesting、value depth、iterations、deadlineを一つのbudgetとして全reader/compositionへ注入する。
  3. Canonical invariant: transform mapをinternal derived cacheにし、spec mutation/edit-layer replacementで必ず無効化または再構築する。
  4. Portable synchronization: cacheを一つのcompiler-checked Sendable実装へ統一する。
  5. Executable capability ledger: format/value/schema/composition envelopeをfixtureと公式oracleへ一対一で結ぶ。
  6. Responsibility split: parser production、value decoding、composition phase、test fixtureを責務単位へ分割する。
