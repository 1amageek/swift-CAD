# Rolling-ball child graph composition verification

This unit closes M4.S.RG/P.RG: complete normalized child position graphs are
consumed by one original rolling-ball minor-arc producer and the existing DI
graph binder. Concrete source intake accepts Native curves and finite nonperiodic
Native-surface lifts with rational B-spline or affine/constant-U/V pcurves,
including mixed children. Other source/pcurve families, periodic/general surfaces,
priority images, M5 composition, general M6 consumers and M7/M8 remain required
open work. Whole-seven remains 1/7; full87 is incomplete.

## Actual source path

The immutable Curve3D snapshot retains the existing Native/lift source binding.
Existing child preparers issue complete charts once. The sealed normalized graph
family retains original coverage, source, laws, support and proof depths; graph
rebinding shares retained arrays and coefficient owners through COW. No sampled
proxy curve, fitted controls or intersection solve is introduced.

The rolling-ball family validates the matching child owners and identity curve
parameter transports. It retains every nonempty closed child enclosure triple,
including singleton intersections and guard-empty triples. The source producer
embeds each child's parameter as U and its auxiliaries into disjoint coordinates,
then adds the three radial-length/half-angle witnesses. Original U/V are the only
authored source parameters. All child equations, support/endpoint restrictions,
denominators and branch guards survive. Canonical polynomial construction supports
variable permutations without assuming the original monomial order.

Native and graph entries share the original minor-arc formula and construction
policy. The old Native protocols, family/preparer and DI entry remain available.
The additive graph domain retains exact selected UV and every guarded auxiliary
preimage. It validates/imports every query coordinate before an empty-selection
shortcut and supports per-template auxiliary arity. No consumer reconstructs UV
from XYZ or treats an enclosure as material proof.

`Verify.py` assembles actual production source with imports-only transformations.
Unchanged cached dependencies are admitted against existing M6 source/product/log
receipts before use. The unchanged Native rolling-ball fixture executes against
the shared producer with only the assembly module name changed. No broad CADCore,
CADGeometry, Kernel or L2-L6 rebuild is performed.
