# Early CS candidate-limit verification

## Scope and implementation

Base: `209a5b46a483dff39b71a3d2174f38d24cd88ce0`. Independent branch:
`codex/cs-early-limit-optimization`, with its own build paths.

The Native CS publisher transports the existing candidate ceiling into the
existing L4 closure capacity using their minimum. Complete incidence requires
exactly one closure per selected cell. L4 validates the retained source and
inherited depth, then rejects insufficient capacity before affine refinement,
closure construction or pair intersections. Final publication checks remain.
No source identity, approximation, public limit, solver, cache or admission
reset is introduced. No partial receipt is returned on failure.

Public paths: ordinary/callback rich and discrete CS, and the explicit exact
admission overload, use `NativeExactCurveSurfacePointProducer`. Its downstream
parameter resolver issues incidence once; the CS geometric resolver consumes
that evidence without issuing additional closures. The existing publication
failure adapter maps `closureLimit` to `resourceLimitExceeded`.

release on arm64 macOS. Normal and Embedded WASM use the matching
`swift-6.4.0-RELEASE_wasm` and `swift-6.4.0-RELEASE_wasm-embedded` SDKs,
`wasm32-unknown-wasip1`, and Node.js 24.19.0 WASI Preview 1. Embedded uses

Already successful shape groups were not repeated.

## Paired performance

`comparison.json` records three interleaved fresh-process measurements of each
version and ceiling, with identical input and admission bounds and no task
builds during measurement. Times are medians of Native Debug proof processes,
including the same L5 entry fixture; they are not isolated query timings.

| Ceiling / outcome | Before | After | Median reduction |
|---|---:|---:|---:|
| 1 / explicit rejection | 5.843827 s | 0.366975 s | 93.72% |
| 5 / explicit rejection | 5.838414 s | 0.362616 s | 93.79% |
| 6 / complete successful relation | 5.836909 s | 5.809082 s | Within observed spread |

| Admitted query payload | Before rejection | After rejection |
|---|---:|---:|
| Work | approximately 5,876,439 | approximately 345,982 |
| Cumulative generated bytes | 267,837,496 | 16,193,780 |
| Storage admission callbacks | 1,690,197 | 100,934 |

The successful ceiling-6 relation retains 267,838,416 generated bytes and
1,690,200 storage callbacks in both versions. Work varies by three units with
iteration order. No successful-query speedup, allocator-count reduction,
peak-memory reduction, Release-mode or WASM timing improvement is claimed.
`baseline.json` preserves an earlier calibration overlapping task builds; its
timings are not used for the comparison. Immutable before/after binary hashes
and the baseline production hashes bind the measured versions.
